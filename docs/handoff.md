# Handoff

The state of memo-extract as of 2026-10-20, written so that someone (or some model) with no access to the original working session can continue. Read [AGENTS.md](../AGENTS.md) for the working rules and [how-it-works.md](how-it-works.md) for the plain-English overview.

## Status at a glance

- **Works end to end**: synthetic gold data (11,587 memos), a deterministic date resolver, a suggestion layer that reproduces all six product examples from correct labels, training with vocabulary pruning and distillation, two-graph ONNX export at int8, evaluation of both labels and user-facing suggestions, and a web playground.
- **Best small model**: `bert-mini-v8k-silver-kd`, 8.0 MB int8, 0.775 strict F1 on test. The teacher (`minilm-l6`, 23.7 MB) scores 0.783. The smallest usable models are `bert-tiny-v8k-silver` and `bert-tiny-v8k-silver-kd` at 2.9 MB, 0.704 and 0.710 strict F1. All four get the six product examples exactly right. See "Results".
- **Not done**: no app integration, no on-phone measurement, the plain-code layer is Python only, and more labelled data is the clearest lever. See "Open work".
- **Tests**: about 1,260, all passing, under 10 s.

### How a memo flows through the model

Training: `data.load_memos` → `records.parse` → per epoch `augment.augment` → `encoding.encode` → length-bucketed batches → `MemoTagger.forward` (span heads see the gold spans) → `model.loss` (+ `distill_loss` with a teacher) → AdamW. After each epoch the dev set is decoded and scored, and `model.pt` is saved only when dev strict F1 improves.

Inference: tokenise → `encode` gives hidden states and per-layer tag logits → constrained Viterbi on content tokens (no `I-X` without `B-X`/`I-X` before it) → spans ordered by first token, ACTION first on ties → `span_heads` on the decoded spans → argmax attributes and pointers → `build_memo` post-processing → `suggest`.

Model details:

- **Span representation**: hidden states of the span's first and last tokens, concatenated, projected to 128 dimensions with GELU and dropout, plus a span-type embedding.
- **Attribute heads**: one linear layer per (type, attribute); six heads in all.
- **Pointer heads** (`owner`, `anchor`): bilinear query·key score / √128 + a learned distance bias over span-index offsets clamped to ±8, against a learned null target at index 0. Disallowed source→target types are masked with a finite −1e4, so the graph stays safe under fp16 and int8.
- **Loss**: unweighted sum of 10 cross-entropies (2 tag layers, 6 attributes, 2 pointers), `IGNORE = -100` for positions that teach nothing. Distillation adds the temperature-scaled KL on the same 10 outputs: `(1 - w) * hard + w * soft`.
- **Truncated or unrepresentable spans** (cut by `max_len`, or glued to text the tokenizer cannot split, like "jazz🎺") get `IGNORE` tags and are dropped from training. No memo in the data exceeds 140 tokens, so `max_len=160` never truncates today; at inference anything beyond it is silently ignored.

### Invariants that are easy to break

1. **Tuple order is the class index.** Reordering `SPAN_TYPES`, any attribute tuple or `TAG_LAYERS` loads old checkpoints without error and scrambles their predictions. Only append, then retrain. `manifest.json` does not carry the label vocabularies, so an app must use the same tuples.
2. **`Pointer.allowed` is not saved in checkpoints** (non-persistent buffer). Changing `OWNER_TARGETS` or `ANCHOR_TARGETS` silently changes masking for old torch checkpoints. ONNX exports bake it in.
3. **ONNX head outputs are positional**: attribute heads in `ATTRIBUTES` order, then pointers in `POINTERS` order. `OnnxTagger` slices by position.
4. **Span order** (by start, ACTION first on ties) must be identical in data and in decoding, because the pointer distance bias works on span-index offsets.
5. **Null and ignore differ**: pointer target 0 (none) is taught; `IGNORE` is not.
6. **Same first name means same person** throughout labels, validation, decoding, metrics and name swaps. Two different Sams in one memo always merge.
7. **Stale artefacts survive**: `sweep.py` skips training and export when their outputs exist, and `log.jsonl` appends across reruns. Delete the run directory to retrain.

Known decoder gaps (not yet fixed): a self-owner can come out when the model points a first mention at a later mention of the same entity (0 occurrences on test); ACTION nesting is not enforced, so 4 of 500 test predictions from the 8 MB model cross an ACTION edge and fail validation; explicit call and message reminders ignore the relation, so "Remind me to call her" after "Priya's mum is having surgery" becomes "Call Priya about her surgery".

Test coverage gaps: no tests for the model forward pass and masking, the losses, `train`, an end-to-end `predict`, ONNX export parity, `agreement`, `score_suggestions`, `registry`, `merge`, `validate` or `pseudo_label`.

## Deploying to a phone

Nothing has been integrated into an app yet. This is the contract an app has to implement. A throwaway Python reference that used only `tokenizers`, onnxruntime and numpy reproduced `decode.predict` on 500 of 500 test memos, so the steps below are complete.

### The two ONNX graphs

Exported by `memo_extract/export.py` (opset 18, IR 10, dynamic `batch`, `tokens`, `spans` axes).

`encoder.int8.onnx`:

| | Name | Type | Shape |
| --- | --- | --- | --- |
| in | `input_ids` | int64 | [batch, tokens] |
| in | `attention_mask` | int64 | [batch, tokens] |
| out | `hidden` | float32 | [batch, tokens, H] (H = 128 tiny, 256 mini, 384 MiniLM) |
| out | `tags_entity` | float32 | [batch, tokens, 13] logits |
| out | `tags_action` | float32 | [batch, tokens, 3] logits |

`heads.int8.onnx`:

| | Name | Type | Shape |
| --- | --- | --- | --- |
| in | `hidden` | float32 | the encoder's `hidden`, unchanged |
| in | `span_bounds` | int64 | [batch, spans, 2]: first and last token index, inclusive, counting `[CLS]` as 0 |
| in | `span_types` | int64 | [batch, spans]: index into `SPAN_TYPES` |
| in | `span_mask` | bool | [batch, spans] |
| out | `attr_PERSON_pronoun`, `attr_EVENT_event_type`, `attr_EVENT_followup`, `attr_ACTION_action_type`, `attr_ACTION_timing`, `attr_FACT_fact_type` | float32 | [batch, spans, n_values] |
| out | `pointer_owner`, `pointer_anchor` | float32 | [batch, spans, spans + 1]: column 0 is "none", column j is span j − 1 |

The label tables are not stored in any exported file; copy them from `constants.py`, in order:

| Table | Order (index 0 first) |
| --- | --- |
| `SPAN_TYPES` | PERSON, RELATION, INTEREST, EVENT, DATE, ACTION, FACT |
| `tags_entity` | O, B-PERSON, I-PERSON, B-RELATION, I-RELATION, B-INTEREST, I-INTEREST, B-EVENT, I-EVENT, B-DATE, I-DATE, B-FACT, I-FACT |
| `tags_action` | O, B-ACTION, I-ACTION |
| pronoun | unknown, she, he, they |
| event_type | other, birthday, anniversary, wedding, baby, job, interview, exam, medical, travel, move, performance, party, school, loss |
| followup | none, ask_outcome, wish_luck, congratulate, check_in, gift |
| action_type | other, message, call, ask_outcome, check_in, wish_luck, congratulate, gift, meet, send |
| timing | unspecified, before, on, after |
| fact_type | other, job, home, relationship, diet, health, pet, feeling, dislike |

A `labels.json` written by the exporter would remove this hand-copying; it does not exist yet.

### Steps per memo

1. Tokenise with `tokenizer/tokenizer.json` (BERT WordPiece: lowercase, accents stripped, `[CLS] … [SEP]`), truncate at `max_len` (160, from `meta.json`), and keep each token's character offsets into the original text. The pruned `-v8k` vocabularies use PAD 0, UNK 1, CLS 2, SEP 3; the full BERT vocabularies use 0, 100, 101, 102.
2. Run the encoder on batch 1.
3. Content tokens are those whose offset start differs from its end (this skips `[CLS]` and `[SEP]`). For each layer, run Viterbi over the content tokens' logits: never start with `I-`, and `I-X` may only follow `B-X` or `I-X`. Raw logits give the same paths as log-softmax.
4. Group `B`/`I` runs into spans. Order them by first token, the ACTION layer before the entity layer on ties, then type, then last token. Pointer indices refer to this order, so copy it exactly.
5. Run the heads with the spans (with zero spans, pass one masked dummy row or skip the heads). Take the argmax of the head for each span's type, and for pointers the argmax over the first `n + 1` columns, only for span types that can carry that pointer. There are no confidence thresholds.
6. Post-process exactly as `decode.build_memo` does: character bounds from offsets, `snap_to_words`, break owner cycles, `link_nicknames`, repoint every pointer to the first mention (`records.first_mention`), `harmonise_mentions`.
7. Run the plain-code layer (`dates.resolve`, `suggest.suggest`, `templates`) on the result.

### What has to be ported

| Piece | Source | Size | Notes |
| --- | --- | --- | --- |
| Tokeniser | Hugging Face `tokenizers` | 150 to 250 lines by hand for WordPiece, or a library binding | Must return character offsets. Avoid Ettin exports, which need byte-level BPE |
| ONNX Runtime glue | `export.OnnxTagger` | about 20 lines | Create both sessions once (about 20 ms) |
| Viterbi and span assembly | `decode.py` | about 50 lines | |
| Post-processing | `decode.py`, `records.py` identity helpers, `TITLES` | about 110 lines | |
| Date resolver | `dates.py` | about 760 lines, a third of it tables | Python regex features to translate: named groups `(?P<x>)`, backreferences `(?P=x)`, `m.expand`, lookbehinds, `fullmatch`. Use date-only types so time zones never shift dates |
| Suggestions and templates | `suggest.py`, `templates.py` | about 280 lines | Templates are keyed like translation strings |
| Label tables | `constants.py` | about 70 lines | Order is part of the model contract |

`names.py` is not needed on device. The best way to prove a port is a parity test: dump the Python spans and `suggest()` output for `data/test.jsonl` and `playground/prompts.json` and diff the port's output against them.

### Gotchas for the port

- **Character offsets.** Python offsets count code points. Swift `String` indices are grapheme clusters and Kotlin/Java indices are UTF-16 units, so memos with emoji or accents misplace spans unless offsets are converted.
- **int8 output depends on the batch.** Dynamic quantisation picks one activation scale per tensor, padding included. The published int8 metrics were computed at batch 64 (strict 0.775); a phone running batch 1 gets 0.773. fp32 is batch-independent.
- **Threads.** On this desktop the 8 MB encoder alone takes a median 0.72 ms at int8 on one thread (1.62 ms fp32), and more threads barely help. `latency_ms_1thread` in `metrics.json` is the whole Python `predict()`, which adds about 0.5 ms of tokeniser and glue. `suggest()` adds about 0.08 ms.
- **Truncation is silent**: tokens beyond 160 are dropped. No memo in the data exceeds 140 tokens. `MAX_MEMO_CHARS` (700) is checked only on labelled records.
- **Runtime**: `MatMulInteger` and `DynamicQuantizeLinear` will most likely run on the CPU execution provider, not CoreML or NNAPI (untested). The minimum mobile ONNX Runtime version for opset 18 / IR 10 is unchecked.

### Suggestion-policy quirks found while mapping (not yet fixed)

- Explicit reminders drop the relation: `Context.recipient` passes `relation=None`, so "ask Priya how it went" anchored to her mum's surgery is titled "Ask Priya how her surgery went".
- A deadline range ("renew the insurance by Friday") is scheduled at its start, which is clamped to today, with `confirm: ["date"]`.
- Past dates are moved to today without a confirm reason.
- `suggest(..., contacts=["", ...])` raises `IndexError`; the server strips blank contacts first, so only direct callers hit it.
- Contact matching compares the raw first word, so "Dr Rahul" matches contacts named "Dr …", and nicknames never match.
- When several DATE spans time one thing, the first one that names a day wins.
- `after_christmas` always uses the current year.

### Playground

`tools/serve.py [--host 127.0.0.1] [--port 8765] [--threads 1]` serves `playground/index.html` ("Memo Bench") and a small JSON API:

| Method and path | Request | Response |
| --- | --- | --- |
| `GET /api/models` | | every model found: `runs/*/model.pt` as `<name>:torch`, `models/onnx/*/` with both graphs as `<name>:onnx-int8` / `onnx-fp32` |
| `POST /api/predict` | `{texts: [...] (1 to 500), models: [ids], today?: "YYYY-MM-DD", contacts?: [names], day_first?: bool}` | `{model_id: [{ms, spans, suggestions}]}` |
| `GET /api/prompts`, `POST /api/prompts` `{text, note?}`, `DELETE /api/prompts/<id>` | | the shared saved prompts in `playground/prompts.json` |

Models are rediscovered on every request (the page's ↻ button), so a new run or export appears without a restart. ONNX models in the playground and in `tools/evaluate.py` always run on one thread; `--threads` only affects torch models. One global lock serialises predictions, and loaded models are never evicted. There is no authentication, and query strings are not parsed (`/api/models?x` returns 404).

## How the data was made

All data is synthetic. Claude agents wrote and labelled it through the scripts in `workflows/`, run with the Claude Code Workflow tool. Every agent ran on Claude Opus 5.5.

1. **Briefs** (`tools/make_briefs.py`): seeded and reproducible. Each brief sets `n`, one of 6 styles (dictated, typed-tidy, typed-quick, shorthand, recap, mixed), 3 of 25 topics, 2 of 7 date styles, 30 first names and 8 surnames. Names come from `memo_extract/names.py`; the six product examples' names (Maya, Daniel, Alex, Priya) are held out.
2. **Pilot** (`workflows/memo-data-pilot.js`, spec v1, 6 briefs × 40 memos): the writer labelled its own memos and a blind relabeller labelled them again. Whole-memo agreement was 72%, but in the 68 disagreements the writer was right 20 times and the relabeller 42 (6 neither), so labelling at generation time was judged unreliable. The adjudicators' recurring errors and spec suggestions became spec v2. Pilot data is kept for reference and is not used in training.
3. **Gold, spec v2** (`workflows/memo-data-v2.js`, 196 briefs, 11,600 memos): a writer writes text only (medium effort), annotators `a` and `b` label blind in parallel (high effort), an adjudicator resolves every disagreed memo (high effort). Every agent validates its file with `tools/validate.py` until it passes. Two copies of the workflow ran side by side on the two halves of the briefs, because each workflow runs at most 16 agents at once.
   - Whole-memo agreement: 7,198 of 11,600 (62.1%). Adjudicator verdicts on the 4,402 disagreements: `a` right 1,874, `b` right 1,715, neither 801, dropped 13.
   - Main disagreement kinds: DATE anchors, FACT and EVENT boundaries, missing DATE and FACT spans, followup values.
   - Two spec edits went in mid-run before adjudication started: RELATION identity is noun plus owner, and three DATE anchor tie-breaks (a date at the end of a request anchors to the ACTION; a date for when something was learned has no anchor; an unanchored relative time anchors to the event it counts from). Some annotator files predate them; the adjudicators applied them.
   - Cost: 392 agents and about 37.6M subagent tokens per half. Median agent time: writer 71 s, annotator 6.5 to 7 min, adjudicator 3.5 min. Wall time was 4h19m, including a 2h25m pause at the account usage limit.
4. **Merge** (`tools/merge.py`): keep a memo when `a` and `b` agree exactly (`agreed`, 7,198) or the adjudicator wrote a record for it (`adjudicated`, 4,389).
5. **Unlabelled texts** (`workflows/memo-unlabelled-texts.js`): 500 briefs × 60 = 30,000 memos, writers only, 500 agents, 27.8M tokens.
6. **Silver labels** (`tools/pseudo_label.py`): the teacher `runs/minilm-l6` labelled the 30,000 texts in about 3.5 minutes. Predictions are kept only when they pass the full record validator: 29,883 (99.6%). The decode-time fixes `harmonise_mentions` and `snap_to_words` raised the yield from 94.5% to 99.5% on a trial set.

Data caveats:

- **Spec drift.** Briefs double-labelled before the two mid-run spec edits used the older RELATION identity and DATE anchor rules. Adjudication came later and used the final spec, but memos both annotators agreed on early were never re-checked.
- **Spliced memos.** Some writers glued two memos into one. These were caught only when the annotators disagreed (several of the 13 drops). Spliced memos that both annotators labelled the same way are still in the data, and the unlabelled `u*` texts likely contain some too.
- **Learning-curve subsets** were cut inline: shuffle the lines of `data/train.jsonl` with `random.Random(0)` and take the first 25% and 50%.
- `runs/calib/*` were trained on an earlier interim merge (1,784 memos) that no longer exists; `runs/teachers/*` on the later one in `data/interim/` (6,522). Neither feeds anything downstream: silver and KD both use the top-level `runs/minilm-l6`, trained on full gold.

### The scratchpad collision

In the v2 gold run the two annotators of a brief shared the session scratch directory, and some wrote helper scripts with the same names (`label_d000.py` and so on), overwriting each other's. The agents themselves reported it in 35 of 196 briefs: d000, d001, t001, t003, t005, t015, t022, t026, t037, t044, t047, t052, t054, t058, t060, t079, t086, t089, t090, t100, t106, t108, t111, t114, t117, t121, t137, t147, t153, t156, t157, t159, x001, x004, x007. No brief reached 90% agreement, and the affected briefs averaged 0.632 agreement against 0.618 for the rest, so there was no measurable leakage and all data was kept. For a contamination-free check, score test on the other seven test briefs (x000, x002, x003, x005, x006, x008, x009). `workflows/memo-label-extra-30k.js` gives each agent a private `SCRATCH/<id>/` directory; do the same in any new workflow.

## Reproducing everything

From a fresh clone with the backbones downloaded. The data steps need Claude Code; everything else runs on a CPU.

```sh
uv sync

# 1. Briefs (already in data/briefs/)
python3 tools/make_briefs.py --split pilot --count 6 --per-brief 40 --seed 1 --prefix p > data/briefs/pilot.json
python3 tools/make_briefs.py --split train --count 180 --per-brief 60 --seed 11 --prefix t > data/briefs/train.json
python3 tools/make_briefs.py --split dev --count 6 --per-brief 50 --seed 22 --prefix d > data/briefs/dev.json
python3 tools/make_briefs.py --split test --count 10 --per-brief 50 --seed 33 --prefix x > data/briefs/test.json
python3 tools/make_briefs.py --split unlabelled --count 500 --per-brief 60 --seed 44 --prefix u > data/briefs/unlabelled.json

# 2. Agent data (already in data/raw/): run workflows/memo-data-v2.js and memo-unlabelled-texts.js (see workflows/README.md)

# 3. Merge gold (already in data/)
python3 tools/merge.py --briefs data/briefs/train.json data/briefs/dev.json data/briefs/test.json --out data

# 7. Students on gold + silver, with and without distillation; then the learning curve
.venv/bin/python tools/sweep.py experiments/distill.json --jobs 1 --threads 8
.venv/bin/python tools/sweep.py experiments/learning-curve.json --jobs 1 --threads 8
```

`tools/merge.py` writes `<out>/<split>.jsonl` for every split named in the briefs it is given, even when the merged list is empty, so a wrong `--first`/`--second` on the train briefs can wipe `data/train.jsonl`. The `u*` briefs all have split `unlabelled`, so merging them writes `<out>/unlabelled.jsonl`. Merge anything new into a separate `--out` first. When the two annotators agree it keeps annotator `a`'s record.

`tools/sweep.py` skips training when `runs/<name>/model.pt` exists and skips export when `models/onnx/<name>/encoder.int8.onnx` exists, but always re-evaluates, so rerunning a sweep is also how to refresh `metrics.json` and `runs/summary.md` after an evaluation or suggestion change. The best run's exact command, from `runs/bert-mini-v8k-silver-kd/sweep.log`:

```sh
.venv/bin/python tools/train.py --train data/train.jsonl data/silver.jsonl --dev data/dev.jsonl --out runs/bert-mini-v8k-silver-kd --threads 8 \
  --backbone=models/backbones/bert-mini-v8k --teacher=runs/minilm-l6 --distill-weight=0.5 --lr=0.0003 --epochs=10
```

Its full config (`runs/bert-mini-v8k-silver-kd/meta.json`): batch 32, encoder lr 3e-4, head lr 1e-3, weight decay 0.01, 6% warmup then linear decay, max_len 160, name-swap rate 0.5, dictation rate 0.25, seed 0, distill weight 0.5, temperature 2.0, 10 epochs. It took 27 minutes at 8 threads.

Learning rates came from a calibration grid on interim data (`runs/calib/*.log`): bert-tiny 1e-3, bert-mini 3e-4, MiniLM 3e-4, ettin-17m 5e-4, bert-small 2e-4, ettin-32m 3e-4. Most calibration runs were still improving at their last epoch.

How to read it:

- **Size.** Gains shrink fast above 8 MB: the 23.7 MB teacher is 0.008 strict F1 ahead of the 8 MB student, and bert-small and ettin-32m (29 to 33 MB) are no better than the teacher.
- **Recipe ladder.** bert-mini-v8k: 0.745 gold only → 0.759 with silver → 0.775 with silver and KD. bert-tiny-v8k: 0.674 → 0.683 KD only → 0.704 silver → 0.710 silver and KD (the two silver tiny models are a wash on reminders).
- **Learning curve** (bert-mini-v8k, gold only): 25% of the training memos → 0.679, 50% → 0.716, 100% → 0.745. Still rising by about 3 points per doubling.
- **Torch vs int8**: BERT models lose 0 to 0.014 strict F1 at int8 (`runs/summary.md` has both); Ettin loses 0.018 to 0.039.
- **Where the best model is weak**: per-type int8 F1 is PERSON 0.995, RELATION 0.939, DATE 0.909, ACTION 0.851, EVENT 0.809, INTEREST 0.774, FACT 0.715. The weakest checks are ACTION anchors (0.785), DATE anchors (0.85) and ACTION timing (0.855). By style (teacher), tidy typed memos score best (0.879) and shorthand worst (0.715).
- **Against people**: two independent annotators reach 0.918 strict and 0.864 reminders against each other (see "How the data was made"), so the best small model is about 0.14 strict and 0.21 reminders short of a careful person.
- **Reminder errors** (before the template fixes, 669 gold test reminders): the teacher got 70% exactly right and the 2.9 MB model 61%. The main misses were near-miss titles (17% for tiny), wrong or missing person (8%) and wrong date (5%).
- **Latency** numbers were re-measured on an otherwise idle machine. Older numbers in the session history (for example 1.29 ms for the best model, 4.22 ms for the teacher) were measured while other training jobs shared the CPU.

## Decisions and dead ends

| Decision | Why |
| --- | --- |
| Encoder tagger plus plain code, not a generative LLM | The smallest useful LLMs (SmolLM2-135M and up) were 6 to 12× bigger, about 300× slower per memo on one CPU thread (3 to 10 s), needed constrained decoding to emit valid structure, could still invent dates, and would take 5 to 18 h to fine-tune here. Plain code is testable, portable and cannot hallucinate |
| The phone's own dictation, not our own speech-to-text | Dictation-style augmentation (lowercase, no punctuation) makes the model robust to it |
| Two BIO tag layers (entities, actions) | An ACTION ("ask Kofi how it went") contains other spans whole |
| Writer, two blind annotators, adjudicator | In the pilot, labels written at generation time lost to a blind relabel 20 to 42 |
| Keep going at 62% agreement rather than restart | Most disagreements were genuine ambiguity; fixed with spec tie-breaks before adjudication |
| Vocabulary pruning (`-v8k`) | The embedding table is most of a small BERT (3.9M of bert-tiny's 4.4M parameters). Pruning to 15,102 pieces is exactly lossless (identical dev curves) and cuts bert-tiny from 4.9 to 2.9 MB and bert-mini from 11.9 to 8.0 MB |
| Teacher: MiniLM-L6 | Beat bert-small on dev (0.790 vs 0.778) and is faster. bert-base was worse (0.764 after 5 of 8 epochs) and 5× slower |
| Silver plus distillation | Distillation on gold alone gave nothing (dev 0.6899 vs 0.6898; earlier on interim data 0.602 vs 0.618). It pays once the teacher labels extra text: bert-mini 0.745 → 0.759 with silver → 0.775 with silver and KD |
| KD by mapping student piece ids into the teacher vocabulary (`student_to_teacher_ids`) | Tokenising twice and checking alignment broke under augmentation, which can merge words differently for a pruned vocabulary. The mapping holds by construction because the pruned vocabulary is a subset of the teacher's |
| Drop the Ettin family | It loses 2 to 4 points at int8 (17m: 0.764 → 0.725, 32m: 0.792 → 0.774), likely activation outliers in the ModernBERT design. Per-channel quantisation recovered only to 0.729. It also tokenises differently, so it cannot be a token-level KD teacher for BERT students |
| Per-tensor dynamic int8 (MatMul, Gemm, Gather) | Per-channel gives BERT nothing (0.7025 vs 0.704) and crashes ONNX Runtime in the heads graph (`MatmulInteger: b zero point is not valid`) |
| Reminder titles fall back to the plain form rather than risk bad grammar | "Check in with Omar about his had tonsils out" became "Check in with Omar" (`FINITE_VERB` in `templates.py`); pronoun rewriting in explicit actions only swaps object pronouns |
| `reminder_intent_f1` alongside `reminder_f1` | Exact title matching over-penalises near-misses; intent compares (person, kind, date) |
| Pseudo-labels must pass the full validator | Silver obeys the same structural rules as gold |
| Nicknames linked by a prefix heuristic (`link_nicknames`) | A coreference head was not worth it yet; "Bob" for "Robert" is not linked |

Not tried: Ettin-32m as a silver labeller only (its fp32 score is the best, 0.792); pruning Ettin's 50k BPE vocabulary; a coreference head.

Known limitations of the evaluation: the vocabulary was pruned using every text including dev and test, so every test word piece is guaranteed kept, which may slightly flatter pruned models on wording never seen. All latencies are desktop CPU, one thread.

## Incidents and lessons

- **Usage limits.** All three big workflows paused at the account usage limit for about 2h25m and resumed by themselves. Stopping a workflow loses its in-flight agents: when `memo-label-extra-30k` was stopped, 16 agents were running and none had finished, so it produced nothing.
- **Scheduling.** `pipeline()` queued all 392 labelling jobs before any adjudication under the 16-agent cap, so dev and test gold arrived last even though they were listed first. Put dev and test in their own workflow, or order stages so adjudication is not starved.
- **Spec edits during labelling.** Agents noticed the spec change on disk and re-read it. Consistency across briefs is mixed; prefer to finish spec changes before launching.
- **Bugs worth remembering.** transformers 5 silently ignores `BertTokenizerFast(vocab_file=...)` (everything became `[UNK]`; pass `vocab=dict`). The tokenizer key is `offset_mapping`, not `offsets_mapping`. The Ettin tokenizer returns no `token_type_ids`.
- **First Codex review: 14 findings, all real, all fixed with tests.** RELATION owner cycles crashing `suggest()`; a missing `gift_relation` template; `rewrite_action` with no owner; negative `Content-Length` bypassing the body limit; same-noun RELATIONs merged across owners; `same_as` never predicted; truncated spans still taught; unicode lowercasing changing lengths; name swaps merging two people; weak KD alignment; a clock-only DATE beating a real date; ambiguity lost when merging dates; call and message templates ignoring the relation; unchecked JSON types in the server.
- **Shell.** The agent Bash tool ran zsh: an unmatched glob is fatal, `path` is tied to `PATH`, unquoted variables do not word-split, and `pkill -f <pattern>` kills its own shell when the pattern is in its command line (use `pkill -f "[t]rain.py"`). ZFS reports `du` sizes lazily right after writes; use `ls -la`.
